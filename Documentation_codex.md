# Aegis Browser Documentation

## 1. Project Overview

Aegis Browser is a desktop browser built with:

- React 18 + TypeScript for the UI
- Vite for the frontend build and dev server
- Tauri 2 for the desktop shell and native webviews
- Rust for backend commands, navigation gating, security, and SQLite migrations
- `@tauri-apps/plugin-sql` for persistent storage

The app is designed around a single main window with:

- A collapsible left sidebar
- A tab strip with tab grouping and drag/reorder support
- A browser viewport backed by native Tauri webviews
- Docked side panels for bookmarks, history, downloads, settings, notes, and embedded web apps

The codebase is intentionally split into two major halves:

- Frontend state, chrome, panels, and storage orchestration in `src/`
- Native window behavior, navigation rules, secure storage, and database migrations in `src-tauri/src/`

## 3. Runtime Flow

1. `src-tauri/src/main.rs` starts the Rust app and calls `app_lib::run()`.
2. `src-tauri/src/lib.rs` creates the Tauri builder, installs the SQL plugin, registers the navigation plugin, and exposes Tauri commands.
3. The frontend loads from `index.html` -> `src/main.tsx` -> `src/App.tsx`.
4. On startup, the app loads persistent state from SQLite:
   - tabs
   - settings
   - bookmarks
   - history
   - downloads
   - tab groups
   - workspaces
   - sidebar state
   - window state
5. The current visible tab determines whether the main viewport shows the home screen or a native webview-backed page.
6. A separate panel webview is created only for web-app panels such as ChatGPT, Spotify, Messenger, Twitch, and WhatsApp.

## 8. Persistence Layer

### `src/services/storage.ts`

This is the main persistence service for the frontend.

It uses:

- `@tauri-apps/plugin-sql`
- SQLite database `sqlite:silentx.db`
- migration helpers
- optional migration from legacy `localStorage`
- Tauri commands for secure secrets

### Database initialization

- `getDb()` lazily loads the SQLite database and caches the connection
- `initializeStorage()` runs once and:
  - applies migrations
  - migrates legacy `localStorage` data

### Migration path

The service includes migration logic from older schema versions:

- Migrates workspaces from `meta`
- Migrates tab groups from `meta`
- Migrates old `tabs` into `tabs_v2`
- Migrates old `downloads` into `downloads_v2`
- Marks `downloads_v2` entries that were `in_progress` as `paused` on startup so they can resume

## 9. Download Manager

### `src/services/downloads.ts`

`downloadManager` is an in-memory controller for download state.

Behavior:

- Maintains the current downloads array
- Notifies subscribers when state changes
- Simulates progress with timers
- Persists each update to SQLite
- Supports:
  - start or resume
  - pause
  - cancel
  - retry
  - delete
  - clear all
  - auto-resume pending downloads on startup

Important note:

- This module simulates progress locally rather than handling real network transfer code in the repo
- The UI and persistence layers treat the entries like real downloads, but the current implementation is timer-driven state progression

## 10. Webview Management

### `src/hooks/useWebviewManager.ts`

This hook is one of the core technical pieces of the app.

It manages:

- main tab webviews
- the docked panel webview
- sync/reposition logic on resize and layout changes
- hide/show behavior for overlays
- safe cleanup on unmount

### Tab webviews

For each web tab:

- Calls `allow_navigation` before creation
- Creates a native `Webview` attached to the current window
- Uses a workspace-specific profile directory:
  - `profiles/workspace_<workspaceId>`
- Waits for the `tauri://created` event before considering the webview ready

### Panel webviews

For embedded web-app panels:

- Resolves the URL from `WEB_APP_PANELS`
- Creates a separate native `Webview`
- Uses a panel-specific profile directory:
  - `profiles/panel_<panelId>`
- Keeps it resized and aligned to the panel container

### Overlay handling

If the omnibox dropdown or a modal is open:

- the active tab webview is hidden
- the panel webview is hidden

This prevents native webviews from visually covering HTML overlays.

### Cleanup

- `destroyTabWebview()`
- `destroyPanelWebview()`
- `destroyAll()` on unmount

## 11. Navigation Safety

### `src-tauri/src/navigation.rs`

This file provides the `silentx-navigation` Tauri plugin.

Main responsibilities:

- Approve frontend-initiated navigations
- Allow in-site navigation and redirects
- Intercept cross-origin navigations from child webviews
- Forward new-tab requests back to the main window
- Emit page-load and click-activity events to the frontend

### Navigation rules

Allowed immediately:

- the main window webview
- frontend-approved URLs
- short redirect chains after frontend navigation
- same-host navigations inside an existing webview

Intercepted:

- cross-origin navigations from child webviews
- `window.open()`
- `target="_blank"` link clicks
- middle-click new-tab actions
- blank-target form submissions

### Anti-duplication and logging

- Debounces repeated emits for the same URL
- Redacts sensitive query parameters before printing logs

Sensitive parameter examples:

- token
- access_token
- refresh_token
- password
- secret
- api_key
- code
- session

### Activity signaling

The injected script emits internal pseudo-links such as:

- `sx-internal://user-click`
- `sx-internal://open-new-tab`

These are used only as control signals inside the navigation layer.

## 12. Injected Webview Script

### `src-tauri/src/injection.rs`

This file returns a JavaScript payload injected into child webviews.

It does the following:

- Intercepts `window.open()`
- Intercepts:
  - Ctrl/Cmd click
  - middle click
  - `target="_blank"` / `target="_new"`
- Intercepts blank-target form submissions
- Adds a custom context menu for links
- Emits click/activity notifications back to the parent window

The custom context menu includes:

- Open link in new tab
- Open link in current tab
- Copy link address

This approach avoids relying on third-party pages to cooperate with the Tauri IPC bridge.

## 13. Rust Commands

### `src-tauri/src/commands.rs`

Exposed Tauri commands:

- `allow_navigation`
- `navigate_webview`
- `set_webview_muted`
- `clear_profile_data`
- `encrypt_secret`
- `decrypt_secret`

### `allow_navigation`

- Allows only these URL schemes:
  - `http://`
  - `https://`
  - `file://`
  - `data:`
- Registers the URL in the navigation state

### `navigate_webview`

- Navigates a webview by label
- Finds either:
  - a standalone webview window
  - or a child webview under the main window
- Marks the label as frontend-initiated so redirects stay allowed briefly

### `set_webview_muted`

- Runs JavaScript inside the matching panel webview
- Mutes or unmutes all `<audio>` and `<video>` elements

### `clear_profile_data`

- Deletes a specific profile directory inside the app data folder
- Used to wipe workspace or panel browsing data

## 14. Secure Secret Storage

### `src-tauri/src/security.rs`

This module implements OS-protected secret storage.

On Windows:

- Uses DPAPI through `CryptProtectData` and `CryptUnprotectData`

On non-Windows targets:

- Falls back to a simple XOR-based placeholder implementation

Frontend-facing commands:

- `encrypt_secret(plaintext) -> ciphertext hex`
- `decrypt_secret(ciphertext_hex) -> plaintext`

This powers:

- scratchpad notes
- saved logins in the settings panel

## 16. Frontend Behavior in `App.tsx`

### Startup sequence

When the app mounts:

- storage is initialized
- tabs/settings/bookmarks/history/downloads/groups/workspaces/sidebar/window state are loaded in parallel
- downloads are rehydrated into `downloadManager`
- pending downloads are auto-resumed
- the active workspace and tab are restored
- the window size/position is restored when available

### Startup mode

`settings.startupBehavior` supports:

- `previous` - restore the last session
- `home` - open a fresh home tab

### Active tab handling

The app derives `activeTab` from the visible tabs in the current workspace.

If the active tab no longer exists after filtering:

- it falls back to the first visible tab
- or a new home tab if needed

### Workspace filtering

Tabs are filtered by workspace using:

- `tab.workspaceId`
- or the parent group workspace
- defaulting to `personal`

If a workspace has no tabs, a home tab is created automatically.

### History recording

Whenever the app opens or navigates to a URL:

- it appends to the in-memory history array
- it persists history to SQLite

### Navigation actions

- `openInput()` normalizes search/address input and either opens a new tab or navigates the active tab
- `navigateTab()` updates tab state and invokes the Rust navigation commands
- `switchHistory()` handles back/forward history
- `reloadActive()` asks the Rust side to reload the webview and recreates it if needed

### Closing and grouping

- Closing a tab records it in `closed_tabs`
- Grouped tabs automatically dissolve the group when only one tab remains
- `closeTabGroup()` closes all tabs in a group
- `groupTabsTogether()` creates a new group
- `addTabToGroup()` and `removeTabFromGroup()` update membership

### Workspaces

- `handleCreateWorkspace()` creates a new workspace and switches to it
- `selectWorkspace()` switches context, keeps or creates a home tab, and closes non-pinned overlays

### Native events

The frontend listens for Rust-emitted events:

- `silentx-open-link`
- `silentx-tab-pointerdown`
- `silentx-page-load-started`
- `silentx-page-load-finished`

These drive:

- new-tab creation from intercepted links
- hiding side panels when the user clicks inside a webview
- loading indicators
- webview URL/title updates

### Context menus

The app uses Tauri native menus for:

- tab actions
- group actions
- page actions

This is separate from the injected in-page link context menu used by child webviews.

## 22. Important Implementation Notes

- The browser uses native Tauri webviews, not an iframe-based browser surface.
- The app persists state in SQLite rather than browser localStorage for current data.
- Legacy localStorage is only used as a migration source.
- Embedded web-app panels are separate native webviews with their own profile directories.
- Profile clearing happens by deleting the corresponding profile directory, then recreating the webview.
- The download manager is stateful and timer-driven in the current codebase.
- The codebase contains some overlapping constant modules:
  - `src/constants/webApps.ts`
  - `src/constants/panels.ts`
  - `src/utils/browser.ts`
  The active app logic primarily uses the shared browser utility module and type-level panel checks.

## 24. Short Summary

Aegis Browser is a Tauri-powered desktop browser that combines:

- native webview tabs
- workspace-aware session organization
- grouped tabs
- side panels for common browser tasks
- embedded web-app panes
- SQLite persistence
- OS-backed secret storage

The strongest technical themes in the project are:

- webview orchestration
- persistence and migration
- navigation gating for safety
- compact, highly customized browser chrome
